# ADR-0011 研究问题框架：从单一 PICO 泛化为三框架＋入口确认

- 日期：2026-09-17；状态：已被 ADR-0012 取代；来源：grill-with-docs 会话（三轮 16 问 live exchange）——用户拍板范围、框架目录、HITL 形态、自定义口径与文档落点。
- 上下文：med-lit-review 此前以 PICO 为唯一研究问题框架：入参写死「研究问题 PICO＋中英关键词表」，§2、检索策略、提取卡、ST-02 校验都按 P/I/C/O 四要素。PICO 经变体（PICOT／PICOS／PECO）可扩，临床前研究也用（模型系统当人群），但「无干预、无对照」的疾病知识、机制盘点类问题套不进；行业内对机制类问题无公认框架（核过 UCD／City／JBI／TMU／Mayo 汇总，不存在叫 TOPIC 的主流框架）。缺的是一层「按问题类型选框架 → 系统化研究问题 → 用户一次确认」的入口，而不是把单一框架硬撑到所有问题。
- 决定：
  - 收录 3 个经典框架为主目录：PICO（人群／干预／对照／结局，可选扩展格：研究类型／时间）、PEO（人群／暴露／结果）、PCC（对象／概念／情境）；其余问题走自定义槽位或用户指定框架（未收录也照用，标注「用户指定：<名>」）。
  - 判定映射（住 references/question-frameworks.md）：干预/对照/效果/安全性 → PICO；暴露/风险/病因/相关因素 → PEO；领域摸底/疾病知识/机制盘点/无干预无对照/拿不准 → PCC；用户点名框架顺用户；都不像 → 自定义草案＋确认。
  - 入口新增「研究问题确认」断点，紧随路线问、独立一问、P0–P3 都问：确认物＝框架名＋槽位逐项填充稿＋一句中文系统化研究问题；关键词初稿由槽位稿推导、只读附注不单列确认项；改选框架致稿不匹配允许一次补问重拟；prompt 已写明框架仍确认一次；AFK 按推荐框架＋问题稿继续、断点记日志、缺口进局限。
  - §2 研究问题节＝标题带框架名＋槽位填充＋一句话系统化问题；框架判定与推荐理由进检索策略与筛选日志、不进 §2；检索策略按所选框架槽位记概念组（组内同义 OR、组间 AND；情境类槽位一般只作限定）；拆包为任务级框架，子包套不进时该包 §2 记一行偏离说明。
  - 校验：ST-02 由「研究问题缺 PICO 要素」改为「按 §2 声明框架查槽位条目齐全，并查「系统化研究问题」行」；自定义与用户指定框架不校验槽位（只认声明）；无声明行按旧 PICO 口径兜底（历史包兼容）；级别仍 warning。
  - 改动只到问题定义层：七列证据表列语义、证据分级口径、提取卡结构不动（卡内要素行名由「PICO」改为「研究要素」，其「对应本文研究问题」引用改指系统化问题一句话）；非临床证据（体外/动物）缺口如实记局限，另立议题。
- 备选（未采纳）：固定 PICO（覆盖不足，即本次痛点）；全量 7 框架（＋SPIDER／PIRD／CoCoPop／ECLIPSE，维护与确认负担重）；自由文本问题（不可机器校验、跨任务不一致）；框架确认并入路线问同一 ask（框架改选后无重拟空间）；未收录框架折叠进最近主框架（丢失用户点名语义）；自定义槽位按条目数校验（用户拍板不校验）。
- 后果：同一 skill 的包会以不同框架呈现（§2 标题自带框架名，人读可辨）；PICO 仍是最高频推荐位与验收夹具形态；ST-02 与 evals 夹具同步（新增 1 条非 PICO 合法包＋1 条缺槽位包）；CONTEXT.md 新增三词（研究问题框架／框架槽位／系统化研究问题）；P1/P3 快线不因换框架改变交付形态。
- 修订（2026-09-17，落地时）：自定义与用户指定框架不校验槽位；提取卡要素行改名「研究要素」；ST-02 对无声明行包严格沿用旧 PICO 口径（对拍 HEAD 版脚本验证：全部历史夹具与工作区包零漂移）。
