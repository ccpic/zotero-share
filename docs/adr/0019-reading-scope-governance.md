# ADR-0019 研读规模治理：推荐区间、单包即全部与规模确认

- 日期：2026-09-18；状态：已接受；来源：grill-with-docs 会话（七轮 18 问 live exchange ＋ 修正一轮）——用户拍板机制形态、数字处置、HITL 落点与选项档位、命名与落点。
- 上下文：原「研读默认」句（`本地附件优先；核心二十至四十篇、正文三千至六千字；超范围分主题拆包`）为初始脚手架初值（commit `3cc79bc`，2026-09-16），此后无改动、无 ADR、无 HITL 交互点、无校验规则、无验收断言。会话核实其**三处语义缺失**：①「超范围」触发条件未定义（超篇数还是超主题宽度）②拆包后每包约束未明文 ③拆包总量封不封顶未明文——用户当场质疑其不可读。实测样本：myelofibrosis 队列 28 → 全文 13 → 证据行 10；ruxolitinib 队列 30（未研读）——均未触及 40。覆盖缺口实测分层：执行层（15/28 未取全文，含 4 篇关键试验）、发现层（PERSIST-1 主报告池中未见）、规则层（未建卡／会议摘要／叙述综述禁入综合）。
- 决定：
  - **单包即全部（不拆包）**：取消「超范围分主题拆包」；超出推荐量的部分不丢——留池备查（合并池可追溯、不上队列）。
  - **20-40 数字不动、改称推荐区间**：拍板机制已解决「上限卡住」问题；两个实测样本均在区间内，无证据支持放宽。
  - **正文去数字化**：删「三千至六千字」约束；正文体量自适应（不设固定字数）。
  - **新增「规模确认」**（独立命名、不占交互点编号）：位于 Step2 分桶完成后、Step3 下载开始前；下载在组（P0／P2）每次必问；拍板语义＝研读目标量；agent 报「建议值＋理由」并展示「目标→队列（含冗余）」两数；选项＝推荐档／扩展档（约 2×）／全量档（核心尽取）／自定；AFK 按推荐档直走。
  - **队列联动**：队列量按拍板目标量换算（含冗余、预期获取率透明）；`download-queue.txt` 据此定稿（＝Step3 输入）；拍板值与来源记筛选日志。**2026-09-20 修订（队列口径明文，grill 会话七问）**：队列量＝`max(核心证据层最深位次 D, ⌈目标量 N ÷ 预期获取率 p⌉)`——D 为本轮核心证据层在 S 降序终池中的最深处位次（关键试验与肾结局分析、系统综述与荟萃、现行指南与共识、真实世界研究各层位次读数须在 ask「依据」中给出）；三档队列各按本口径独立取大、选项行标注覆盖边界（含 {最深处证据}）、取大后只取整不缩边界；ask 题面出示「队列来历（覆盖至 S 序第 M 位）」与两约束读数；筛选日志规模确认行加「队列覆盖位次｜获取率对照（预期／实际）」字段，实际值 Step3 采信后回填、供下轮估价校准（实例：ARNI CKD 2026-09-19 队列 520＝含 KDIGO 2025 #514，预期获取率 60–70%／实际 57.4%＝292/509）。术语「队列覆盖位次」入 `CONTEXT.md`「研读规模」区；问法原文与模板同步见 `med-lit-review` 的 `hitl-protocol.md` 规模确认节与 `screening-log-template.md` 规模确认行。
  - **2026-09-20 二次修订（队列口径被 ADR-0032 取代）**：上一条的队列口径（`max(核心证据层最深位次 D, ⌈目标量 N ÷ 预期获取率 p⌉)`、覆盖边界标注、「队列覆盖位次」字段）已被 **ADR-0032** 取代——下载队列改为「研读选取集」，规模确认的拍板对象改为篇数 N（下载＝入库＝研读三集合一），入库范围由队列全量改为研读集。取代依据为 ARNI CKD 2026-09-19 实测：队列 520 的位次侧驱动项 KDIGO 2025 ADPKD #514 未被研读、460/520 队列条目从未被读、研读集有全文率（38/60＝63%）与队列整体获取率（57.4%＝292/509）同档。本 ADR 其余决定（单包即全部、20–40 推荐区间、规模确认这一交互点本身、第一判据的历史记录）继续有效；术语「队列覆盖位次」随 ADR-0032 自 `CONTEXT.md` 删除，「未选取」接替原「队列截断」的披露位。
  - **第一判据记录**：覆盖完备（冲突时宁大勿小）——本次决策链的评估基准。
- 备选（未采纳）：**保留并重定义拆包**（语义三缺补齐成本高，且实测从未触发）｜**上限放宽到 20-60**（无样本支持，且「卡住」已由拍板机制解决）｜**入口第三问**（入口时信息不对称——用户不知道池况）｜**研读前确认（下载后）**（下载成本已投入，选择失真）｜**不设确认点、只写明显式覆盖通道**（用户明确要求在检索后下载前有真实选择）｜**完全取消篇数上限**（自动读全量、无用户决策）｜**规则层一并重估**（未建卡出口／摘要信号／叙述综述进表——波及 R3 文献红线与分级规则，另开议题，本次只列缺口清单）。
- 后果：四处文档联动——`SKILL.md`（研读默认行改写；输入输出节拆包句删除；HITL 章引导句与门位表加行；路由表 Step3 输入列改「规模确认后队列」）；`references/protocols/hitl-protocol.md`（新增「规模确认」节＝唯一问法原文；总则／入口节／跳步记法与「两处断点」表述同步）；`references/templates/screening-log-template.md`（跳步记法节加「规模确认行」）；`CONTEXT.md`（新设「研读规模」区，立「研读目标量」——三量辨析：研读目标量／队列量／实得量）。历史交付（`workspace/**`）冻结不动——2026-09-18 前交付沿用旧口径。**规则层缺口清单**（本次只记录、不处置）：①未建卡禁入综合的出口 ②会议摘要禁支撑结论的信号可见性 ③叙述综述不进证据表。
- 接口注意：在途的「引文扩展轮」（`CONTEXT.md`「检索发现」区）亦位于下载前——若引文扩展并池重排先发生，规模确认应基于含扩展的终池；先后关系由两条工作线定稿时对齐。**2026-09-18 对齐（两条工作线均已定稿，本注记闭环）**：「引文扩展轮」定于 Step2 首轮排序完成后、规模确认之前执行（单轮 1-hop；种子＝终池头部 20＋指南/SR 判定集；并池重跑 Step2 重排后再进队列），「迭代补漏」同窗（各记其账、并池重排一次）——故规模确认一律基于含扩展与补漏的终池。机制细目见 `.scratch/search-coverage/tickets/02-citation-expansion-round.md` 与 `.scratch/search-coverage/tickets/05-iterative-gap-filling.md`。
