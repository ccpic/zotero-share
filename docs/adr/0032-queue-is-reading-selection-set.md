# ADR-0032 队列即研读选取集：下载、入库与研读同一集合

- 日期：2026-09-20；状态：已接受；来源：grill-with-docs 会话（四轮 20 问 live exchange；scout 影响面清单 50 条、逐条带 `文件:行号`）。
- 上下文：现行链路的队列口径由 ADR-0019（2026-09-20 修订）定为「队列量＝`max(核心证据层最深位次 D, ⌈目标量 N ÷ 预期获取率 p⌉)`、S 降序前缀、宁大勿小」，入库范围＝队列全量（`placement-plan.md` 计划行数＝`agent/download-queue.txt` 条目数）。**ARNI CKD 2026-09-19 实测**：终池 1564 → 队列 520 → 下载输入 509 → 实获全文 292 → 写库 520（附件 288／无附件 219／既有 11／待挂 2）→ 研读 60（有全文 38／仅摘要 22）→ 证据表 52 行／参考文献 60 条。用户诉求：结论参考 60 篇而入库 400+ 篇的落差不可接受（「固定成进入结论的一套文献」）。核实三处事实后确认队列口径本身失效：① **队列 520 的驱动项未被研读**——位次侧取到扩展档覆盖边界 KDIGO 2025 ADPKD #514（目标侧仅 ⌈60÷0.65⌉=93；`screening-log.md` 规模确认行），而 #514（`10.1016/j.kint.2024.07.009`）不在研读集、未进结论，460/520 条目从未被读；② **研读集本来就不是截线**——研读 60 的终池位次散布 1–491、中位 70.5，是按相关性的判断选取；③ **宽队列没有换来可及性**——研读 60 有全文率 38/60＝63%，与队列整体获取率 57.4%（292/509）同档，冗余下载未被任何机制消费。
- 决定：
  1. **三集合一**：下载队列＝研读选取集＝入库集（＝研读对象），成员一次选定、三处同用。队列件名与逐行 DOI 形态不变（`agent/download-queue.txt`；剪队列不改写本件），首行口径句与各消费方文案改写。
  2. **入库集＝有卡集**：可及性为「有全文」或「仅摘要」的选取成员才建条目；**仅题录成员一律不建条目、不入库**（含指南／监管／书章这类不适用摘要的文种下载不到者），只在可及性清单与 §8 逐条交代（DOI），无例外口（日后需要走人工单篇归置）。
  3. **选取协议＝类型必取＋排序补足**：必取层＝与本问题直接相关的现行指南／共识、系统综述与荟萃、关键试验主报告、**监管文件（B2 并入必取层，单一入口）**，由 agent 出判定件、随规模确认出示、用户可增删；补足层＝按 S 降序补足到 N；**必取不计入 N 上限，m>N 时以 m 为 N**。无摘要条目按题名可判者照选，进选取集后走 R5a 三级取数。**必取层一律在池内圈定**：判定件出现池外 DOI 即 fail-closed（退出码 2，逐条列出并指去 B1／B2 手工补充路径或重跑检索），不静默纳入。
  4. **写库时点不变**：写库仍在研读之前（Step4 位置与两侧输入输出不动），范围由「队列全量」改为「选取集 − 仅题录成员」——该集合在下载与摘要取数完成后即可判定，与随后产生的有卡集逐条一致（建卡守恒 R5 是其保证；新增门禁见决定 8）。
  5. **规模确认改义**：确认对象＝篇数 N（N 现在同时是研读＝下载＝入库篇数）；题面删「双约束取大」与覆盖边界句，改出示「必取 m 篇＋补足到 N 篇」清单预览与「预计可得全文 ≈ N×获取率，余下按摘要级研读」；档位＝推荐／扩展／自定（「全量档」原义＝覆盖边界最深，退场）；「获取率对照（预期／实际）」保留为披露字段（实际值＝本轮选取集全文实得率）。
  6. **选取留痕**：新增机器件 `run/b1/selection.json`（逐条 DOI｜层（必取／补足）｜依据｜S 位次）＋筛选日志一行汇总；覆盖账第九块由「队列截断」改为「**研读选取**」，指针段含 `selection.json`。
  7. **披露**：§8 第 10 类机制句改为「未选取」披露——未选取＝终池 − 选取集，按**来源池**（`origin`）与 S 位次分档汇总，明示未逐条验证纳入与全文；原「截线外条目属队列截断而非漏检」的辩护句退场（新口径下这些条目本就未被选取，不作漏检断言）。注：证据类型只在研读时判定（选取时刻不可得），故披露维取来源池而非类型。
  8. **新增硬门禁**：落点计划条目集 ≡ 有卡集（逐键比对，差异即判不过；卡面与落点计划都在包内、离线可算），把用户诉求写成可验证断言。
  9. **人读主件首屏**：三个数字改为「检索候选（终池）／研读选取／证据表行」；「下载队列」标签退场，hover 口径与读者面词表同步。
  10. **P1 不产队列件**：P1 停在发现与分桶，产出候选清单（＝`agent/doi-list.txt`）＋四桶报告（＝`agent/bucketing-and-sources.md`，全池行集，由 `step2_select.py pool-ledger` 产出）；升格 P0 时重跑 Step2 重排并选取，**先删除 P1 遗留的全池台账骨架**再由 `apply` 首写新骨架（否则首写不生效、全池行集留到 P0）。
  11. **第一判据改判**：覆盖完备性只由终池与覆盖账承担，研读与入库按相关性精取——判决基准＝「库内条目＝进入结论的一套」（取代 ADR-0019 的「覆盖完备，冲突时宁大勿小」）。
- 备选（未采纳，均带理由）：**队列维持宽、只钉入库集**（库干净，但下载耗时、灰色暴露与失败面不变，诉求只解决一半）｜**队列＝选取集＋替补（≈1.5N）**（全文产出更高，但下载集≠入库集、多一层顶替协议；实测宽队列对研读集可及性零增益，收益无证据）｜**读完再写（Step4 后置）**（成员严格＝最终研读集，但流水线改序：交互点三、附件挂载、R5a 的「库内摘要」取数档全部后移；收益由「成员守恒＋剔除走人工」覆盖）｜**纯排序前 N**（机械可复算，但会漏掉深层核心证据——本次 #259/#346 的现行指南一类）｜**机械类型规则圈必取**（会把只有字面相关的指南收进必取；KDIGO 2025 ADPKD 即此类，驱动队列 520 却未被研读）｜**必取设上限／N 为总上限**（核心证据被篇数目标截断，与「必取」语义矛盾）｜**未选取提供补入库通道**（收尾勾选或常态命令——库与结论集的对应关系被稀释，与诉求相反）｜**仅题录留空位／B2 保持直取直归**（不变式出现例外口，门禁与披露都要分叉）｜**覆盖账两块并存／只留终池读数**（前者双口径易读成两个数，后者披露变薄）｜**P1 照产选取集／P1 保留旧前缀语义**（P1 无研读意图，预演集无人读；双口径并存更糟）｜**队列件改名为 selection-queue.txt**（五处消费方与指针、契约件全链改名，零语义收益）。
