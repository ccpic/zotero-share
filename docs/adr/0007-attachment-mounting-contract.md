# ADR-0007 入库挂载口径：本地直挂＋补漏环＋既有条目默认补挂（硬门禁）

- 日期：2026-09-17；状态：已接受；来源：grill-with-docs 会话（三轮 12 问 live exchange＋收束确认）。
- 上下文：隔离盲测（10 号票）写库 27 条全数成功，但库内 27 条**零附件**——设计资产 03 §4 有「先下载后入库挂载（`attach_pdfs.py`）」主链路，却在内化落字时丢失：SKILL.md／placement-guide／落点报告模板／门禁都没有挂载动作与断言；执行体按落字契约行事不算违约，门禁 78/78 全绿也拦不住（本地实际有 22/27 可挂，84 篇下载 PDF 身份核验全过）。缺陷由用户复看盲测库暴露（`issues/13-attachment-mounting-gap.md`）。
- 决定：
  - 挂载为 Step4 写库回查后的默认步骤（不另行确认）：本轮条目本地已验明身份 PDF 直挂（不重抓）；缺 PDF 者按全文链补漏环再抓一轮（下载策略按现行默认：竞速含灰色，ADR-0006），验明身份后补挂；仍缺 → 断点＋局限声明，不重复打断。
  - 既有条目（库内已存在未重写）：children 已有正文附件（contentType=application/pdf）→ 跳过；没有 → 默认补挂（只写子附件，不动元数据与收藏集）。
  - 附件回查（children）＋落点报告附件列（逐条「已挂／无 PDF」＋计数行）；无 PDF 条目的条目键进局限声明。
  - 门禁：硬门禁「落点回查一致」扩为「落点与附件回查一致」（新增 D-08 附件回查 live fail-closed、D-09 披露断言；自检增附件缺口变异；断言 78→80）。
  - `use-zotero/references/placement.md` 全文链补一句：任务已下载且验明身份的本地 PDF 直挂、全文链只补漏。
- 备选（未采纳）：不重抓、缺者仅记断点；既有条目仅在确认后补挂；附件只声明不入门禁（门禁无牙正是本次缺陷未被拦截的根因）。
- 后果：med-lit-review 交付的库内条目默认带全文附件；写路径从「只建条目」扩到「条目＋子附件」——隔离测试库的零写入比对须把附件子条目计入范围；e2e 门禁新增两条断言（78→80）并含附件缺口变异自检；盲测库按本口径补挂修复（留痕见 `issues/13-attachment-mounting-gap.md`）。
