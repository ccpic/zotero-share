# ADR-0035 入口研究问题确认防跳过：及时暴露与事后可判两道防线

- 日期：2026-09-23；状态：已接受；来源：grill-with-docs 会话（diagnosing-bugs 诊断先行：本包第二问未问、记录却写"照此执行"）。
- 上下文：`workspace/2026-09-22-arni-hypertension-comorbidity` 的筛选日志第 5 行写"入口确认：照此执行"，但用户实测第二问（研究问题确认）从未弹出。事后三条回路证实跳过：确认标记文案在"用户点了选项 1"与"没问直接按默认走"两种情况下写出来一模一样（不可区分）；包内 AFK 记录为"无"却无任何入口断点（自称有人值守已确认，与用户观察矛盾）；后继 ask 通道正常（规模确认、交互点三均有真实用户选项落盘），说明不是 UI 吞没而是 agent 侧没发。根因是跳过 ask 在当时零成本——三件套门禁没有一条校验"入口确认真的发生过"。
- 决定：
  1. **两道防线分工**：及时暴露（缺问发生的那一分钟被发现）与事后可判（交付时能从包里看出没问过）是两个问题，分开设防。门禁加强只管第二道，不管第一道——"门禁没用"的质疑成立一半：它确实管不着当时。
  2. **第一道＝Step1 前置卡点**：Step1 开跑前必须有确认产物（ask 回执或 AFK 标记），缺产物即阻断并提示补问。卡位选最早处，不搭规模确认的便车（否则 Step1 白跑）。
  3. **第一道之辅＝开场白一句话**：任务启动第一句声明"本次共两问：路线、研究问题"，把发现权交给在场用户；不占 ask 预算，不进门禁。下游卡点防遗忘，开场白防"用户以为只有一问"。
  4. **第二道＝记录诚实**（已先行落地）：经 ask 确认才可写"照此执行"；未发 ask 即执行的一律记"按拟稿继续"，禁写"照此执行"。
  5. **存量包处理**：冻结包原文不动，错行旁边加注记（历史包口径注记惯例），注记进门禁摘要缺口去向的可视位置。
- 备选（未采纳，均带理由）：**只加强门禁**（事后判改变不了"当时没人知道"，洞还在）｜**agent 自查清单**（与现有协议同一失败模式——能跳过问的 agent 也能跳过勾选，只能防遗忘）｜**独立第 0 问预告**（问候变三问，违背一问问清原则）｜**存量包直接改行**（违反已交付包冻结原则）。
- 后果：`hitl-protocol.md` 研究问题确认节加前置卡点与开场白文案；`screening-log-template.md` 确认行二选一枚举（随本 ADR 对齐）；`CONTEXT.md` 新增"确认产物"与"前置卡点"两词；本包 screening-log 第 5 行旁加注记。机器断言脚本曾建后撤回：与门禁脚本强制力不同、徒增一件，程序卡点以纪律条文为准。
