# ADR-0029 卡内段序与默认直出集：渲染层按读者序重排，卡文照录不改

- 日期：2026-09-20；状态：已接受；来源：第 7 轮卡片呈现 polish（grilling 会话：先逐卡盘点卡头与卡内形态，再逐条拍板）。**修订 [ADR-0028](0028-reader-surface-zero-internal-vocabulary.md) 决定 3 的一处边界解释**——0028 说「卡是真源」，本记录补足：**真源地位约束的是文字，不约束段序与呈现形态**。
- 上下文：人读主件的提取卡在读者侧有三处实测毛病。① **卡头不是题名**：60 张里 56 张只有「文献 N · 作者 等 年份」，3 张（`G2／G4／C2` 三个小组卡）因卡首行正则不容纳作者段内的括注而整条失配，把「（全文状态：有全文 PDF p.1–128；本卡实读…）」与内部卡号一起灌进卡头；索引 chip 按 48 字硬切，3 处切在括注中间留残句；关系图节点读屏名取整条 GB/T 引文（≈180 字），与 `reader-html.md` §3.6 约定的短名单不符。② **身份段与段序不成形**：卡内「文献」段是一条 `｜` 连排（实测 60/60 满足同一位置模式：作者｜年｜题名｜期刊卷页｜DOI｜附注，只是被当成一整段渲染）；默认直出集（`CARD_INLINE_FIELDS`）只认字段形态、不认 `##` 小节，于是**同一个名字在这张卡直出、在那张卡折叠**——23 张仅摘要卡把「研究要素／结局」写成小节，读者默认看到的是被折起来的 PICO，「研究要素」60/60 张都有的重要段却不在默认视野里。③ **等级话术无出口**：卡内自写文本里 42×「先验」、40×「定级」、37×「初判」、28×「升降档」、12×「封顶」，而协议只定义 E1–E3 先验映射与「E1 封顶／E5 托底」，页上除一句一行式总述外没有任何档位释义。
- 决定：
  1. **卡内段序＝固定读者序**，按证据表七格词表序排：文献→研究要素→设计与等级→人群→干预与暴露→结局与效应量→与结论的关联→（折叠区同序）偏倚备注→未见未知→可引用摘录→作者自认局限→未登记段保文档序殿后；**段序只对顶层段生效，小节成员跟随其小节**。
  2. **默认直出集按段名派生**（字段与 `##` 小节一视同仁），即七格序的前七段含「研究要素」；缺席不留空壳。折叠区用同一份排序结果，区内的「其余 N 段」标签照旧列名。
  3. **卡文文字零改写**：重排、逐段成行、段名归一都只发生在渲染层；卡片 markdown 一字不动，`--check` 的输入指纹不变。**卡的「照录真源」地位约束文字，不约束段序与呈现形态**（本条即 0028 决定 3 的边界补足）。
  4. **卡头三段式**：题名一行／「作者 等 年份」一行／徽章一行（等级、被引、全文获取）；题名取**卡内身份段第 3 段的源题名**（60/60 可派生，且比证据行「文献」列完整——行里的 GB/T 题名常缺副题），作者年份由身份段派生，**卡首行解析降为兜底**并须剥掉内部卡号与「（全文状态…）」；卡头不再重复「文献 N」（返回链、索引副行与证据行仍带编号）；索引 chip 主行改题名（按标点语义截断＋省略号）、副行给编号·作者年份·等级；8 张背景卡徽章行留一枚「背景文献（未列入证据表）」。
  5. **身份段逐行＋允许附注**：题名／作者／来源／DOI 四行，第 5 段起归「其他标识与附注」（含「本轮读到：PDF p.x–y」，即原独立状态行的页码）；**位置校验**（年份位以四位数年份开头、DOI 位以 DOI 开头，实测 60/60 成立）不通过即**整段回退原样**——不拿猜测的分段误导读者。
  6. **术语剥离改平衡括号扫描**：原正则 `[^）)]*` 遇「括注内套括号」失配，36/60 张卡的字段名整段丢失（`name=''`），并把整条括注留在正文里成了长句；改按括号深度扫描切标签。研究要素的括注**摘出来不丢**：「对应研究问题：…」单列段内首行，P/I/C/O 名称对照降为段名旁小注。
  7. **等级释义入口**：屏上唯一一份释义（五档含义＋话术四句），悬停任一处等级记号都可出；**键盘每卡一枚入口**（落在「设计与等级」段名旁），卡文里的记号不逐枚给 tab 停靠点；ESC 先收释义再关抽屉；打印在筛选条下的定义处展开完整含义表一次（纸上没有悬停）。文案只写协议与本交付实测能支撑的档位含义，**不为 E4／E5 补先验映射**。
  8. **上游同步**：`reading-card-template.md` 把身份段的位置约定成文（作者｜年｜题名｜来源｜DOI｜附注），使后续交付不再依赖运行时猜测；本决定不回溯历史交付。
- 备选（未采纳，均带理由）：**保文档序**（改动最小，但同一名字在不同卡上时而直出时而折叠，读者建立不起预期，正是本轮要治的病）｜**整卡默认全展**（最长的卡近 4,000 字，抽屉沦为不可扫读的长文）｜**改上游卡模板让所有卡同序**（动的是研读真源与逐篇研读成本，且历史交付无法回溯；段序是呈现问题，置渲染层即可）｜**每个等级记号都是可聚焦控件**（单卡多 3–4 个 tab 停靠点，卡区累计约 240 个，键盘读者穿越成本过高）｜**卡内常驻释义**（60 张卡重复 60 遍同一段说明）｜**补齐 E4／E5 先验映射把五档写全**（协议里 E4／E5 无成文定义，补齐等于给这套分级加新定义，属分级学决策而非渲染层取舍——页上按协议＋实测如实写，将来要补另开决策）｜**只修卡首行正则、卡头仍用卡号短引**（解决泄漏，但「卡头没有题名」这条读者诉求落不了地）。
- 后果：渲染层新增段序重排、段名归一、身份段解析与形态兜底四件事，全部确定性、无网络、可 `--check`；卡模板的位置约定成为后续交付的可靠前提。读者面新增五个词（题名／作者／来源／DOI／其他标识与附注），词表唯一家仍是执行体（0028 不变）。关系图节点读屏名回到契约约定的短名单，长详情（整条引文）落 `<title>`。已知残留与代价：① 证据表行头仍是「作者与题名同行」（§3.4 契约），与卡片侧的分行粒度不同——本轮有意不动（改动面在证据表列与门禁上明显更大）；② 页体积增约 71KB（身份逐行与等级记号包装），W-17 体积读数仍在封顶之上（本轮前已超，属既有读数）；③ 卡头三段使折叠行高增加，文献卡区更长。
